| 10 | **CORROBORATED** | Chapter `topics/bodies/topic_10.tex:183-197`, especially line 194, says an offset greater than the segment “length” is an error. The mapped source says the same at `run/di/10/page_003.txt` (source `sources/di/10.pdf`, p. 3). If length means byte count, valid zero-based offsets are `0 <= offset < length`, so `offset == length` must fault. (If the term is intended as an x86 descriptor *limit*, `<= limit` is correct; use “maximum valid offset” or an explicit half-open range to remove the ambiguity.) |
| 13 | **CORROBORATED** | Chapter `topics/bodies/topic_13.tex:213-221`, line 220, defines global unicast as “the remaining” addresses. The mapped source has the same shorthand at `run/di/13/page_004.json` (source `sources/di/13.pdf`, p. 4). It is overbroad as an IPv6 taxonomy: special/reserved/other non-global ranges are not thereby global unicast. Minimal fix: identify the globally routable unicast range (normally `2000::/3`) and label the source wording an oversimplification. |
| 14 | **CORROBORATED** | Chapter `topics/bodies/topic_14.tex:489-499`, line 498, says omitted result type defaults to `int`; mapped evidence `run/di/14/page_004.txt` (source `sources/di/14.pdf`, p. 4) repeats it. In modern C++, a function declaration/definition requires a declared return type; omission is ill-formed. Replace with an explicit-type requirement (`void` for no result), optionally noting implicit-int as obsolete C-era history. |
| 18 | **CORROBORATED** | Chapter `topics/bodies/topic_18.tex:386-419` says a doubly-linked list usually maintains beginning/end pointers (line 398), but `insertAfter` (lines 403-418) receives only `current` and never updates an owning list’s tail when `current->next == nullptr`. If an external owner is intended, the invariant failure is real; pass the list owner/reference and set `last = item` on tail insertion, or explicitly scope the routine to node links and document the caller’s tail update. |
| 19 | **CORROBORATED** | Chapter `topics/bodies/topic_19.tex:363-385` presents `(foldl - 0 '(1 2 3))` as `((0-1)-2)-3`. In Racket, `foldl` calls the combiner with element then accumulator, yielding `(- 3 (- 2 (- 1 0))) = 2` here. Label the Q19 passage Haskell, or give the Racket argument order/expansion. |
| 20 | **CORROBORATED** | Chapter `topics/bodies/topic_20.tex:594-617` redefines `delay` to return `(lambda () x)` (lines 597-600), then `tail` applies native `force` to `(cdr s)` (lines 612-613). Make them separate patterns and say producer–consumer may be implemented with events. |
